# 西交校园平台 — 产品与技术规划

> 在现有「体育打卡」基础上，扩展为多板块校园综合平台。本文档从产品与技术两方面说明需要做的事情。

---

## 一、产品板块总览

| 板块 | 形式 | 核心能力 |
|------|------|----------|
| **体育打卡** | 已有 | 登录 → 签到打卡、查看日志、停止任务 |
| **二手交易** | 闲鱼式 | 发布商品、价格、多图、分类、联系、下架 |
| **考试资料** | 帖子 | 发帖、标题+正文+附件、分类/标签、列表与详情 |
| **面试经验贴** | 帖子+评论 | 发帖、标题+正文、评论、点赞 |
| **学长有话说** | 帖子/短内容 | 学长分享（经验/建议/问答），可点赞、可评论 |
| **西交吃什么** | 结构化+UGC | 餐厅→楼层→窗口→菜品+价格+用户评价 |

---

## 二、各板块功能与数据需求（产品视角）

### 2.1 体育打卡（已有，保留）

- 无需新增数据库表，沿用现有 session + 打卡接口即可。
- 建议：在首页/导航中作为「打卡」入口保留。

---

### 2.2 二手交易（闲鱼式）

**产品功能：**

- 发布：标题、描述、价格、分类（书籍/数码/生活用品等）、多图上传、联系方式（可选脱敏）。
- 列表：分页、按分类/价格/时间筛选、搜索。
- 详情：大图、价格、描述、发布人（学号脱敏）、联系、收藏/想要。
- 我的：我发布的、我收藏的、下架/删除。

**需要存储：**

- **数据库**：商品表（标题、描述、价格、分类、发布人学号、状态、时间）、可选收藏表。
- **图片存储**：每个商品多图，需持久化存储（见第四节）。

---

### 2.3 考试资料

**产品功能：**

- 发帖：标题、正文（富文本或 Markdown）、附件（PDF/Word 等）、课程/考试名称、标签。
- 列表：分页、按课程/标签/时间筛选。
- 详情：正文渲染、附件下载、点赞/收藏。

**需要存储：**

- **数据库**：帖子表（标题、正文、课程、标签、发布人、附件路径、时间）、可选点赞/收藏表。
- **文件存储**：资料附件（PDF 等），见第四节。

---

### 2.4 面试经验贴

**产品功能：**

- 发帖：标题、正文（公司/岗位/流程/心得）、标签（行业/公司类型）。
- 列表：分页、按标签/时间排序。
- 详情：正文、评论列表（树形或平铺）、点赞帖子/评论。

**需要存储：**

- **数据库**：帖子表、评论表（帖子 id、父评论 id、内容、作者、时间）、点赞关系表（帖子/评论 id、用户、类型）。

---

### 2.5 学长有话说

**产品功能：**

- 发布：短内容/长文（经验、建议、问答）、可选分类（考研/就业/科研/生活）。
- 列表与详情：同「帖子」形式，支持点赞、评论。

**需要存储：**

- **数据库**：可与「面试经验贴」共用「帖子 + 评论」模型，用「板块/类型」字段区分；或单独一张帖子表 + 评论表。

---

### 2.6 西交吃什么

**产品功能：**

- **结构化数据**：  
  - 餐厅：朗清苑、惠风苑、和鸣苑、涵英楼负一、同和苑（固定 5 个）。  
  - 每个餐厅 1～3 层（涵英楼负一为 1 层）。  
  - 每层多个窗口，每个窗口有名称。  
  - 每个窗口下有多道菜品，每道菜有名称、价格（可区间如 8–15 元）。
- **UGC**：用户对某道菜/某窗口评价（星级、文字、图片可选）、人均消费。
- 前端：按「餐厅 → 楼层 → 窗口 → 菜品」浏览，查看价格与评价；支持搜索菜品名/窗口名。

**需要存储：**

- **数据库**：  
  - 餐厅表、楼层表（或餐厅+楼层合并）、窗口表、菜品表（名称、价格、窗口 id）。  
  - 评价表：关联菜品或窗口、用户、星级、内容、图片、时间。
- **图片存储**：菜品/评价的图片（若有）。

---

## 三、数据库设计概要

当前项目**没有**使用数据库，仅 Flask + session。要支持以上板块，需要引入**关系型数据库**（推荐 SQLite 开发 / MySQL 或 PostgreSQL 生产）。

### 3.1 通用与用户

- **user**（可选）：若只沿用学号登录，可仅用 `student_id` 作为用户标识；若需要昵称、头像，可建 user 表（id, student_id, nickname, avatar_url, created_at）。

### 3.2 二手交易

- **second_hand_item**：id, student_id, title, description, price, category, status(上架/下架/已出), image_urls(JSON 或关联表), contact, created_at, updated_at。
- **second_hand_favorite**（可选）：user_id, item_id, created_at。

### 3.3 考试资料

- **exam_post**：id, student_id, title, body, course_name, tags(JSON 或单独表), file_path, created_at, updated_at。
- **exam_post_like**（可选）：user_id, post_id。

### 3.4 面试经验贴 / 学长有话说（可合并为「帖子+评论」）

- **forum_post**：id, student_id, board(interview/senior), title, body, tags, created_at, updated_at。
- **forum_comment**：id, post_id, parent_id(可为空，用于楼中楼), student_id, content, created_at。
- **forum_like**：target_type(post/comment), target_id, student_id, created_at。

### 3.5 西交吃什么

- **canteen**：id, name, floors_count（如 3）。
- **canteen_window**：id, canteen_id, floor(1/2/3), name（窗口名称）。
- **canteen_dish**：id, window_id, name, price_min, price_max（或单一 price）, sort_order。
- **canteen_review**：id, dish_id 或 window_id, student_id, rating(1–5), content, image_urls(JSON), created_at。

## 四、图片与文件存储

- **二手交易**：商品多图。  
- **考试资料**：附件（PDF 等）。  
- **西交吃什么**：评价图片（可选）。  
- **学长/面试**：帖子内图片（可选）。

**方案选择：**

1. **本地存储（适合小规模、单机）**  
   - 在项目目录下建 `uploads/`（或按 config 配置），子目录如 `second_hand/`、`exam/`、`canteen/`。  
   - 上传时生成唯一文件名（UUID + 后缀），避免覆盖。  
   - 数据库中存相对路径或 URL 路径（如 `/uploads/second_hand/xxx.jpg`）。  
   - 需在 Flask 中配置静态或路由提供文件访问（注意权限与类型校验）。

2. **对象存储（适合生产、多机/扩容）**  
   - 使用阿里云 OSS / 腾讯云 COS / MinIO 等。  
   - 上传后得到 URL，数据库只存 URL。  
   - 需要：配置 Bucket、AccessKey、域名或 CDN。

**建议：**  
- 先实现**本地存储**，接口设计为「存 path/url」，后续可无缝切换为对象存储。

**安全与规范：**

- 限制文件类型（如图片仅 jpeg/png/gif/webp；附件仅 pdf/doc 等）。  
- 限制单文件大小与单用户总容量。  
- 上传接口需登录态；下载/展示可按业务决定是否公开。

## 五、你现在需要做的事情清单

### 5.1 基础设施

- [ ] **选型并接入数据库**  
  - 开发：SQLite（单文件，无需安装）。  
  - 生产：MySQL 或 PostgreSQL。  
  - 使用 ORM（如 **SQLAlchemy**）便于建表、迁移与维护。

- [ ] **设计并建表**  
  - 按第三节建齐各板块表。  
  - 建议用迁移工具（如 Flask-Migrate/Alembic）管理表结构变更。

- [ ] **统一用户身份**  
  - 目前以 `session['student_id']` 为准；若建 user 表，在登录成功后创建或更新 user，后续所有「发布/评论/点赞」都关联 `student_id` 或 user_id。

### 5.2 图片与文件存储

- [ ] **确定存储方案**  
  - 先实现本地 `uploads/` 目录 + 唯一文件名。  
  - 在 `config.py` 中增加 `UPLOAD_DIR`、`MAX_FILE_SIZE`、`ALLOWED_EXTENSIONS` 等。

- [ ] **实现上传 API**  
  - 通用上传接口（或按板块拆分）：校验登录、文件类型与大小、落盘、返回 path/url。  
  - 前端：表单 `multipart/form-data` 或拖拽上传。

- [ ] **权限与安全**  
  - 仅登录用户可上传；删除/下架仅作者或管理员。  
  - 下载/展示 URL 可做简单鉴权（如带 token）或白名单路径。

### 5.3 各板块后端 API

- [ ] **二手交易**：发布、列表（分页/筛选）、详情、收藏、下架/删除。  
- [ ] **考试资料**：发帖、列表、详情、附件下载、点赞。  
- [ ] **面试经验贴**：发帖、列表、详情、评论（含楼中楼）、点赞帖子/评论。  
- [ ] **学长有话说**：同上，用 `board` 或类型区分。  
- [ ] **西交吃什么**：  
  - 管理端（或初始化脚本）：维护餐厅、楼层、窗口、菜品（含价格）。  
  - 用户端：按餐厅/楼层/窗口查菜品与价格、提交评价、查看评价。

### 5.4 前端与导航

- [ ] **首页/导航**  
  - 顶部或侧边导航：打卡、二手交易、考试资料、面试经验、学长有话说、西交吃什么。  
  - 首页可为「工作台」汇总各板块入口，或按 Tab 切换。

- [ ] **各板块页面**  
  - 列表页、发布页、详情页（含评论、点赞、收藏等）。  
  - 西交吃什么：餐厅→楼层→窗口→菜品的层级展示 + 搜索 + 评价表单。

- [ ] **统一风格**  
  - 沿用现有 CSS 变量与卡片风格，保持与当前打卡页一致；列表用卡片或列表布局，适配移动端。

### 5.5 西交吃什么初始数据

- [ ] **录入餐厅与窗口结构**  
  - 朗清苑(3 层)、惠风苑(3 层)、和鸣苑(3 层)、涵英楼负一(1 层)、同和苑(3 层)。  
  - 每层下窗口名称（需实地或官方信息整理）。

- [ ] **录入菜品与价格**  
  - 每窗口下菜品名称、价格（可后续由管理员或用户补充，先做部分示例数据）。

### 5.6 其他

- [ ] **权限与合规**  
  - 二手交易、发帖、评论均需登录；敏感信息脱敏（学号、手机）。  
  - 内容审核：可选敏感词过滤、举报入口，后续可接审核策略。

- [ ] **依赖**  
  - 在 `requirements.txt` 中增加：Flask-SQLAlchemy、Flask-Migrate、Pillow（图片处理可选）、python-dotenv（配置环境变量）。

## 六、推荐实现顺序

1. **数据库 + 用户**：接入 SQLAlchemy，建 user（可选）及各板块表。  
2. **上传与存储**：本地 uploads + 上传 API，供二手、资料、评价使用。  
3. **二手交易**：从发布到列表、详情、下架闭环。  
4. **考试资料**：发帖 + 附件 + 列表 + 详情。  
5. **面试经验 + 学长有话说**：共用帖子与评论模型，区分 board。  
6. **西交吃什么**：表结构 + 初始数据 + 浏览与评价功能。  
7. **首页与导航**：整合所有板块入口，统一 UI。

按上述顺序，你可以先做「数据库 + 图片存储」，再按板块逐个实现 API 与页面；需要我按某一项（例如数据库建表 SQL、或某个板块的 API 设计）细化成可直接落地的代码，可以指定板块和文件名。
