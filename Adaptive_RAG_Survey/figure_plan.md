# 后续自绘插图方案（当前正文尚未插入图片）

## 图 1：静态 RAG 与自适应闭环 RAG 的对比

- 建议位置：第 1 节第三段之后，用于承接固定流程的失效假设。
- 左图：输入 → 固定 Top-k 检索 → 拼接上下文 → 生成；用三个标注指出“所有问题都检索”“原问题直接作查询”“返回文档全部使用”。
- 右图：输入/生成状态 → 触发判断 → 查询修正 → 检索 → 证据评价 → 生成；证据评价连回查询修正和补充检索，生成前增加停止判断。
- 图注建议：静态 RAG 将检索视为预处理，自适应 RAG 则根据过程状态控制触发、查询、证据与停止。箭头表示信息流，反馈箭头表示条件执行而非必然迭代。
- 对应正文：第 1、2 节，不添加任何实验数值。

## 图 2：基于证据状态的检索与停止过程

- 建议位置：第 6.2 节之后，作为个人理解的机制化总结。
- 将回答需求拆为三个证据槽位 A/B/C，分别标记“已支持”“缺失”“存在冲突”；缺失项进入定向检索，冲突项进入替代来源检索，全部支持且预算允许时进入答案生成。
- 图下单独画“无新增证据/达到预算”通往“停止并披露不足”，避免只画无限成功的循环。
- 图注建议：一种可检验的证据驱动控制设想。槽位状态仍需评价器和人工核验，不表示本文已实现或验证该系统。
- 对应正文：第 6.2--6.4 节，必须保留“本文设想”的边界。

## 制作建议

优先用 TikZ、draw.io 或 PowerPoint 绘制为 PDF/SVG，再导出 PDF 插入 LaTeX。两张图均采用统一颜色：蓝色为生成与判断，绿色为有效证据，橙色为纠正，灰色为停止。不要把代表论文原图拼接为“自绘图”，不要把不同论文的实验数值放在同一坐标轴排名。当前两张中文表格已经承担方法比较与评价框架总结，无需再为凑数量增加装饰性图片。
